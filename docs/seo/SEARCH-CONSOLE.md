# Подключение Search Console и Яндекс Вебмастера

Ручные шаги владельца после того, как `https://semyazdrav.ru` стабильно открывается по HTTPS (сертификат GitHub Pages выпущен, Enforce HTTPS включён). Код сайта для этого уже готов: canonical, `sitemap.xml` (29 URL) и `robots.txt` на месте, проверяется `make check`.

## Google Search Console

1. Откройте https://search.google.com/search-console и добавьте ресурс типа «Доменный» для `semyazdrav.ru` (предпочтительно) или «С префиксом URL» для `https://semyazdrav.ru/`.
2. Подтвердите права:
   - доменный ресурс — TXT-записью в DNS на reg.ru (значение даст консоль);
   - URL-ресурс — HTML-файлом: пришлите файл/токен, его добавят в корень репозитория одним коммитом (сами токены без владельца не генерируются).
3. После подтверждения: «Файлы Sitemap» → отправьте `https://semyazdrav.ru/sitemap.xml`.
4. Проверьте отчёты «Страницы» (индексация) и «Удобство для мобильных» через 1–2 недели.

## Яндекс Вебмастер

1. Откройте https://webmaster.yandex.ru и добавьте сайт `https://semyazdrav.ru`.
2. Подтвердите права: HTML-файл в корень репозитория, метатег в `index.html` или DNS TXT на reg.ru — по выданному значению.
3. «Индексирование → Файлы Sitemap» → добавьте `https://semyazdrav.ru/sitemap.xml`.
4. Включите уведомления о проблемах с доступностью сайта.

## Что смотреть дальше

- Запросы, по которым у статей есть показы без кликов: кандидаты на улучшение title/description (длины держит `check_site.py`).
- Пары статей, конкурирующих за один запрос (риск отмечен в `docs/content/AUDIT-2026-10.md`): решать по фактическим данным, а не превентивно.
- Ошибки сканирования и страницы с кодом не-200: расхождение с `sitemap.xml` ловится сравнением с ожидаемым набором URL в чекере.

Никакие счётчики аналитики этими шагами не подключаются: Search Console и Вебмастер не требуют трекеров на сайте. Решение об аналитике — отдельное, по `privacy.html` её сейчас нет.
